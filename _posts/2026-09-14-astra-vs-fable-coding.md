9 月 1 号 Claude 那边出了 Fable 5.1，3 号 OpenAI 发 Astra。  
时间叠在一起，时间线全是对比图。独立评测有人写 Claude Code + Fable 5.1 略高一截，OpenAI 自己的 Terminal-Bench 又把 Astra 写在前面。我看不进去那些小数点。

我就拿自己的博客仓库做了同一件事：

> 给 CMS 的文章表单加一个可选封面图字段，同步 README，别动主题和其他配置。

一边走 Claude Code（Fable 5.1），一边走 Codex / Astra。都先让它们出计划再改。

## 计划阶段

Fable 更抠文件。会点名 `admin/config.yml`、`media_folder`、front matter 的 `image`。还会多问一句要不要动已有文章——我回不要。

Astra 的计划更「完整」，会提到 SEO、社交预览图、上传目录权限。听着专业，有一半我这站点用不上。我删掉之后它才收敛。

这块跟我八月写的「先计划再动手」对上了：不拦着，Astra 特别容易顺便优化。

## 动手阶段

两边都能改对 yaml。  
差别在边角：

- Fable 改完会自己 `git status` 给你看，范围比较干净
- Astra 有一次把 README 里旧的「不需要后台」段落也顺手改顺了，意思没错，但不是这次要的

UI 习惯也有人吐槽过：Astra 做前端爱整一套很「默认」的卡片布局。我这次没让它碰页面，躲过了。下次让它改首页我大概会写死「不要重做视觉」。

## 钱和速度

同一件事 Astra 轮次更少，但单轮更贵。  
Fable 爱多读几个文件，总时长反而长一点。

网上有人拿长任务测，说 Astra token 账单明显更高、长作业稳定性一般。我这点活测不出来「稳定性崩了」，只能说：**短任务两边都够用，长任务我暂时更信 Claude 那套本地 Agent。**

Codex 走云沙箱的感觉也在。适合「这个 PR 就改这几个文件」。博客这种小仓库还好；Jeecg 那种目录深的，我还是开 Claude Code。

## 我现在的分流

没有冠军。

| 活                              | 我倾向                                    |
| ------------------------------- | ----------------------------------------- |
| 生仓库、长重构、要记住项目规矩  | Fable / Claude Code                       |
| 目标清楚、范围小、想快点出 diff | Astra / Codex                             |
| 解释概念、写邮件、整理面试说法  | 网页里的 Astra 也行                       |
| 默认日常                        | 便宜的 Sonnet / 旧一点的 Opus，别天天顶配 |

还有个很现实的点：Fable 5.1 我 9 月 1 号就能稳定用；Astra 4 号才进我的列表。谁先能用，谁就先占默认位。这比榜单先决定工作流。
